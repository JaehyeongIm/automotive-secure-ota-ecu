# ADR-007: Anti-rollback(다운그레이드 거부) 설계 — 서명 이미지 헤더 + 메타 버전 기준선

| 항목 | 내용 |
|---|---|
| 문서 ID | ADR-007 |
| 상태 | accepted (기준선은 잠정 — ATECC608A 전환 예정) |
| 작성일 | 2026-06-03 |
| 관련 요구사항 | FR-BL-008, FR-AB-008, SR-FW-003, SR-ATK-003, ADR-006 |

---

## 1. Context (상황 · 문제 · 판단 기준)

**다운그레이드 공격**(SR-ATK-003): v2가 v1의 취약점을 고쳤어도, 공격자가 *정상 서명된 옛 v1*을 OTA로 재설치하면 취약점이 부활한다. v1의 ECDSA 서명은 진짜이므로 **서명 검증만으로는 못 막는다**. 별도로 "버전이 현재보다 낮으면 거부"하는 anti-rollback이 필요하다(FR-BL-008).

anti-rollback에는 두 값이 필요하다:
- **들어온 펌웨어의 버전** — 부트로더가 *실행하기 전에*, *위조 불가능하게* 읽을 수 있어야 한다.
- **비교 기준선(현재/최소 허용 버전)** — 전원 리셋에도 남는 NV에, 이상적으로 변조 방지로 저장.

**Decision Drivers:** ① 실행 전 검증(verify-before-execute), ② 버전 위조 방지, ③ 업계 관례(secure boot 이미지 포맷) 정합, ④ ATECC608A(ADR-006)와의 정합.

## 2. 결정 1 — 버전을 어디서, 어떻게 읽나 (이미지 헤더 배치)

부트로더는 새 펌웨어를 *실행하기 전에* 버전을 알아야 한다. `APP_VERSION`은 코드 내부 `#define`이라 실행해야 알 수 있고, 메타데이터 버전은 서명에 묶이지 않아 위조 가능하다. → **이미지에 서명으로 보호되는 버전 헤더**를 둔다. 단, ARM Cortex-M은 점프 시 SP@offset0·PC@offset4를 읽으므로 슬롯 맨 앞 정렬이 중요하다.

- **옵션 A — 앞 헤더 (MCUboot 정석) [채택]**
  `[ 헤더(0x200 패딩) ][ 벡터테이블+코드 ][ ECDSA 서명 64B ]`. 헤더가 슬롯 맨 앞(offset 0), 앱 벡터테이블은 `slot+0x200`. 업계 관례(MCUboot 이미지 포맷)와 동일. 부트로더는 헤더를 offset 0에서 바로 읽고, `slot+0x200`으로 점프한다. **비용:** 앱 링커 origin을 `+0x200` 이동, FLASH length `-0x200`(VTOR 0x200 정렬).
- **옵션 B — 뒤 trailer**
  `[ 벡터테이블+코드 ][ 헤더 16B ][ 서명 64B ]`. 벡터테이블이 offset 0 그대로라 링커 무변경. 장점: 가벼움. 단점: "헤더가 뒤"라 비관례적, 헤더 위치를 size로 역산해야 함.
- **옵션 C — 게이트웨이 제공 버전(다운로드 시 검사)**
  버전을 OTA 프로토콜로 전달. 헤더 불필요하나 버전이 *이미지 서명에 묶이지 않아* 위조 가능 → 신뢰성 낮음.

**채택: 옵션 A(앞 헤더).** 관례적 secure-boot 이미지 포맷을 따른다. ECDSA 서명이 (헤더+코드)를 덮어 `fw_version`을 위조 불가로 만든다.

**구현 영향(앞 헤더):**
- 앱 링커 4종(Sensor/Drive × Slot A/B): FLASH `ORIGIN += 0x200`, `LENGTH -= 0x200`.
- 부트로더: `IMG_HEADER_SIZE`(0x200) 만큼 점프·유효성검사 오프셋(`slot+0x200`), ECDSA 영역은 `size-64`(헤더+코드 자동 포함), 헤더는 `slot+0`에서 읽음.
- **앱 startup/system 무변경**: `USER_VECT_TAB_ADDRESS`가 비활성이라 앱은 VTOR를 설정하지 않고, 부트로더의 `SCB->VTOR = slot+0x200`(점프 직전)에 의존한다.
- 단일 출처(SSOT): `IMG_HEADER_SIZE`/`OTA_ImgHeader_t`를 ota_meta.h에 두어 부트로더·앱·sign 도구가 동일 값을 쓴다.

## 3. 결정 2 — 비교 기준선을 어디에 저장하나

- **옵션 A — 메타데이터 `slot_x_version`(NV, CRC32) [채택, 잠정]**
  부트로더가 CONFIRMED 슬롯의 버전을 기준선으로 사용. 데모 가능. 한계: CRC-only라 변조엔 약함.
- **옵션 B — ATECC608A monotonic counter (정석)**
  변조방지 단조 카운터. 물리 공격까지 차단(Android AVB의 rollback index 패턴). ADR-006 하드웨어 통합 선행 필요.

**채택: 옵션 A(메타 버전).** `slot_x_version`은 OTA 시 헤더의 실제 fw_version으로 기록한다(auto-increment 폐기). 부트로더가 검증 후 헤더 버전을 CONFIRMED 슬롯 최고 버전과 비교, 낮으면 부팅 거부.

## 4. Consequences (결과 · 트레이드오프 · 한계)

| 위협 | 메타(CRC) 기준선으로 차단되나 |
|---|---|
| 실수로 옛 버전 배포 | ✅ |
| 원격 CAN 공격자(OTA 경로) | ✅ (서명 헤더 버전 위조 불가 + 기준선 비교) |
| 물리/ST-Link 공격자 | ❌ 메타(CRC-only) 기준선 위조 가능 |

- ⚠️ **기준선 한계:** 들어온 버전은 서명 헤더로 위조 불가하나, *기준선*인 메타데이터는 CRC-only(서명 아님)라 플래시 쓰기 공격자가 낮게 위조할 수 있다. **실수·원격 다운그레이드는 차단되나 물리 공격엔 미흡**(SR-FW-003 부분 충족). 정석 경로 = **ATECC608A monotonic counter(ADR-006)** → ADR-003(잠금 NV)·ADR-004(seed TRNG)와 같은 "지금은 가능선, 정석은 ATECC608A 후속" 구조.
- ⚠️ **검증 한계:** 링커 origin·점프 오프셋 변경은 빌드 컴파일로는 검증되나 **실제 부팅 성공은 보드 플래시(HIL)로만 확인** 가능. 순수 로직(헤더 파싱·버전 비교)은 호스트 단위테스트로, sign 도구는 Python 자가검증으로 확인.
- **표준:** SR-ATK-003 / UNECE R155 / ISO·SAE 21434(다운그레이드 위협), MCUboot 이미지 헤더 포맷, Android AVB rollback index.
