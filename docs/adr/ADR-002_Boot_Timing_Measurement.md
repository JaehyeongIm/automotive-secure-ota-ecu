# ADR-002: 부트 타이밍(Tboot) 측정 방식 결정

| 항목 | 내용 |
|---|---|
| 문서 ID | ADR-002 |
| 상태 | 확정 |
| 작성일 | 2026-06-01 |
| 관련 요구사항 | FR-AB-004, FR-AB-007, NFR-PERF-003, FR-BL-012 |

---

## 1. 배경

FR-AB-004의 Self-test는 "부팅 후 **Tboot** 이내에 4개 항목을 만족하면 PASS"로 정의된다. 여기서 Tboot(리셋 ~ Self-test 완료/Confirm까지의 시간)는 다음을 좌우하는 핵심 타이밍 값이다.

- Self-test PASS/FAIL 판정 데드라인 (FR-AB-004)
- 3-strike 롤백의 총지연(3 × 부팅시간)이 ISO 26262 FTTI 및 IWDG 윈도우(8000ms, FR-BL-012) 안에 드는지 (FR-AB-007)

Tboot는 임의로 고르는 매직넘버가 아니라 **타깃에서 실측하여 유도**해야 한다(초기 제안 "200ms"는 근거가 없어 폐기). 따라서 "무엇으로 측정할 것인가"를 먼저 결정한다.

특히 Tboot 구간에는 **앱 실행 이전 구간**(클럭 기동, `.data/.bss` 초기화, 부트로더의 ECDSA-P256 서명 검증, App jump)이 포함되며, 소프트웨어 uECC 기반 ECDSA 검증이 Cortex-M4에서 수십~100ms+로 **Tboot의 지배항**이다.

---

## 2. 검토한 옵션

### 옵션 A: DWT Cycle Counter (CYCCNT)

Cortex-M4의 DWT(Data Watchpoint and Trace) 유닛이 제공하는 CPU 사이클 카운터로, 코드 두 지점 사이의 사이클 수를 읽어 시간으로 환산한다.

**한계**

- DWT는 **앱이 활성화한 뒤에만** 동작한다. 리셋~main 이전 구간(특히 부트로더 ECDSA 검증=지배항)은 카운터가 켜지기 전이라 **측정 불가**.
- 측정 대상(DUT)이 자기 시간을 자기보고(self-report)하므로 안전 관련 타이밍 논증의 독립성이 약하다.

### 옵션 B: GPIO 토글 + 외부 관측 (오실로스코프 / 로직 분석기)

부트로더 진입 첫 줄에서 마커 GPIO를 HIGH, Self-test Confirm 시점에 LOW로 토글하고, 외부 계측기로 펄스폭을 실측한다.

**장점**

- 리셋 직후부터의 **실제 wall-clock**을 측정 — ECDSA 검증을 포함한 전 구간을 포착.
- DUT와 독립된 **외부 관측자**가 측정 → 안전 타이밍 논증에 적합.

**한계**

- 외부 계측기(스코프/로직 분석기)가 필요하다.

---

## 3. 표준 관행

ISO 26262의 타이밍 검증은 안전 관련 데드라인을 **독립적 기준(reference)**으로 측정하는 것을 권고한다("측정 대상이 측정 도구를 겸하지 않는다"). 임베디드 온타깃 타이밍 측정의 정석은 **GPIO 마커 + 외부 캡처(wall-clock 실측)**와 **사이클 카운터(코드 구간별 귀속)**의 **조합**이다. 리셋부터의 wall-clock이 필요한 안전 타이밍은 외부 관측이, 앱 코드 내부의 구간 분해는 사이클 카운터가 담당한다.

---

## 4. 최종 결정: 옵션 B를 주(主), 옵션 A를 보조로 채택

| 판단 기준 | 옵션 A (DWT) | 옵션 B (GPIO+Scope) |
|---|:---:|:---:|
| 리셋~main 이전(ECDSA) 측정 | ✗ | ✓ |
| 측정 독립성(안전 논증) | ✗ | ✓ |
| 외부 장비 불필요 | ✓ | ✗ |
| CI 자동화·구간 분해 | ✓ | △ |

- **주 측정(Tboot 확정): GPIO 토글 + 오실로스코프 / 로직 분석기.** 부트로더 진입에서 마커 HIGH, Self-test Confirm에서 LOW → 펄스폭 = Tboot 실측.
  - 로직 분석기/스코프가 없으면 RPi GPIO 타임스탬프(ms급)로 대체 — on-target 벤치에 이미 RPi가 있어 현실적.
- **보조 측정(구간 분해·회귀): DWT CYCCNT.** 앱 진입 후 페리페럴 init vs 첫 heartbeat 등 구간을 분해해 UART/CAN으로 로깅, CI 회귀에 활용(ASPICE SWE.4/5).

확정된 Tboot 실측값은 SRS FR-AB-004 수용 기준에 반영한다(실측 worst-case × 2 이상 여유, IWDG 8000ms 미만).

---

## 5. 제약 사항 및 한계

1. 주 측정은 외부 계측기(스코프/로직 분석기)를 요구한다. 미보유 시 RPi GPIO 타임스탬프로 대체하되 분해능은 ms급으로 제한된다.
2. Tboot의 지배항이 부트로더 ECDSA 검증이므로, 부트로더 빌드(컴파일러 최적화·클럭 설정) 변경 시 Tboot를 재측정해야 한다.
3. 본 ADR은 측정 *방식*만 확정한다. Tboot의 *수치*는 실측 후 SRS에 반영한다.
