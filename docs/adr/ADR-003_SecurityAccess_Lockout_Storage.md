# ADR-003: SecurityAccess 잠금 상태 저장 위치 (RAM vs NV) 결정

| 항목 | 내용 |
|---|---|
| 문서 ID | ADR-003 |
| 상태 | 확정 (잠정 — NV 전환 예정) |
| 작성일 | 2026-06-02 |
| 관련 요구사항 | FR-CAN-010, SR-ATK-006, SR-KEY-003, FR-AB-005 |

---

## 1. 배경

UDS SecurityAccess를 HMAC-SHA256(key=PSK, msg=Seed) 챌린지-응답으로 구현하면서(SRS §13.6), brute-force 방어를 위해 **연속 3회 Key 오류 → 10초 잠금**을 둔다. 잠금 동안 추가 요청은 NRC 0x37(requiredTimeDelayNotExpired), 3회 초과 시 NRC 0x36(exceededNumberOfAttempts)을 반환한다.

이때 "실패 카운터 + 잠금 만료 시각"을 **어디에 저장할 것인가**가 문제다. **ISO 14229(UDS)**는 brute-force 방어를 위해 이 잠금 지연이 **전원 리셋에도 유지**될 것을 요구한다 — 공격자가 ECU를 리셋해 잠금을 초기화하고 무한 재시도하는 우회를 막기 위함이다.

## 2. 검토한 옵션

### 옵션 A: RAM 보관 (채택, 잠정)

`g_sec_fail` / `g_sec_locked` / `g_sec_lock_until`을 RAM 정적 변수로 두고, `uds_init()`(부팅·세션 초기화)에서 리셋한다.

- **장점:** 단순, 즉시 구현, 플래시 마모 없음, 추가 의존성 없음.
- **한계:** 전원 사이클/리셋 시 잠금이 해제되어, 리셋 가능한 공격자는 잠금을 우회할 수 있다(ISO 14229의 "리셋에도 유지" 요건 미충족).

### 옵션 B: NV(Flash) 보관

잠금 상태를 플래시에 기록하여 리셋에도 유지한다(ISO 14229 정석, **AUTOSAR NvM**이 보안 카운터를 NV 블록으로 관리하는 방식).

- **한계:** STM32F446에는 EEPROM이 없어, 플래시 섹터 *erase-before-write* + *쓰기 마모* 를 다루는 스킴이 필요하다. 깔끔하게 하려면 별도 설계 중인 **메타데이터 이중화(섹터 2·3 redundant + CRC32 + seq, FR-AB-005)** 위에 잠금 필드를 얹는 것이 맞는데, **그 구조가 아직 미구현**이라 의존성이 생긴다.

---

## 3. 위협모델 분석 — 왜 RAM이 *잠정적으로* 충분한가

잠금을 우회하려면 ECU를 리셋해야 한다. 본 시스템의 위협모델에서:

| 공격자 | 리셋 가능? | RAM 잠금으로 막히나 |
|---|---|---|
| **원격 CAN 공격자** | ✗ (물리 접근 불가, ECUReset 0x11 미구현) | ✅ 원격 brute-force 차단됨 |
| **물리 접근 공격자** | ✓ (전원/ST-Link) | △ 우회 가능하나, 이미 ST-Link로 플래시 덤프 등 더 큰 침해가 가능하고, *진짜 부팅 관문은 부트로더 ECDSA*라 가짜 펌웨어는 부팅되지 않음 |

또한 Key는 4바이트(2^32)지만 HMAC 기반이라 오프라인 추측이 불가능하고, 온라인 추측은 잠금으로 제한된다. 따라서 **원격 공격에 대해서는 RAM 잠금으로 충분**하며, NV화의 추가 효용은 *물리 접근 공격자*에 한정되는데 그 공격자는 이미 더 강력한 수단을 가진다.

---

## 4. 최종 결정: 옵션 A(RAM) 잠정 채택, NV는 후속 과제

| 판단 기준 | 옵션 A (RAM) | 옵션 B (NV) |
|---|:---:|:---:|
| 원격 brute-force 차단 | ✓ | ✓ |
| 리셋 우회 차단 (ISO 14229 완전 정합) | ✗ | ✓ |
| 구현 단순성 / 즉시성 | ✓ | ✗ |
| 플래시 마모 없음 | ✓ | ✗ |
| 추가 의존성 없음 | ✓ | ✗ (메타 이중화 선행 필요) |

### 구현
- `uds.c`(양 ECU): `g_sec_fail`, `g_sec_locked`, `g_sec_lock_until` RAM 정적 변수. `uds_init()`에서 0으로 리셋. 잠금 만료는 `HAL_GetTick()` 기준 부호 비교(틱 wrap 안전).
- 단위테스트 `test_sa_lockout_after_three_wrong_keys`로 3회→0x36, 잠금중→0x37, 10초 경과→해제를 검증.

### NV 전환 조건
**FR-AB-005의 메타데이터 이중화(섹터 2·3 redundant + CRC + seq)** 구현 후, 그 NV 구조에 `sec_fail_count` / `sec_lock_until` 필드를 추가하여 잠금을 NV로 승격한다 → ISO 14229 "리셋에도 유지" 요건 완전 충족.

---

## 5. 제약 사항 및 한계

1. 전원 리셋 시 잠금이 해제된다(리셋 우회). 원격 위협에는 무력하나 물리 위협에는 미흡 — 이 한계는 SRS §13.6에 명시한다.
2. 잠금 만료는 SysTick(`HAL_GetTick`) 기반이므로, 장시간(>49일) 연속 가동 시 틱 오버플로 경계가 존재하나 부호 비교로 안전하게 처리한다.
3. 본 ADR은 *잠정* 결정이다. NV 전환(옵션 B)은 메타데이터 이중화 작업과 함께 재평가한다.
